# Updating the primary navigation

The primary nav (`ul.nav-list` in the header) is driven by one file:
`_data/navigation.json`. This doc covers how to edit it safely.

## Where nav items live

`_data/navigation.json` is a flat JSON array. `_includes/header.liquid` loops
over it once, in file order, and renders each item.

An item the template actually uses looks like this:

```json
{
  "title": "Dissertation",
  "url": "/dissertation/"
}
```

- `title` — the label shown in the nav.
- `url` — the link target. Internal paths should start and end with `/`
  (e.g. `/dissertation/`), matching how the rest of the site is built.
- `dropdown` — optional array of child items (see below).

`header.liquid` renders items in array order, top to bottom. To change where
an item sits in the row, move its position in the array.

Older versions of this file carried a `"side": "left"` / `"side": "right"` key
on every item. The template never read it, so those keys have been removed —
don't add them back.

A dropdown item:

```json
{
  "title": "Meetings",
  "url": "/meetings/",
  "dropdown": [
    { "title": "Registration", "url": "/meetings/registration/" },
    { "title": "Housing", "url": "/meetings/housing/" }
  ]
}
```

The parent (`Meetings`) is still a real link — its own `url` is repeated as
the first row inside the dropdown, so the parent page is reachable both by
clicking the top-level label to expand it and by the first item once it's
open. Children only read `title` and `url`; they don't support their own
nested `dropdown`.

## Adding, reordering, renaming, removing

- **Add**: insert a new `{ "title": ..., "url": ... }` object anywhere in
  the array. Position in the array is the position in the rendered row.
- **Reorder**: cut/paste objects to move them; that's the only thing that
  controls order (see the `side` note above).
- **Rename**: edit `title` only; `url` doesn't need to change.
- **Remove**: delete the object (or just its `dropdown` array, to keep the
  link but drop its children).
- **External links**: the template checks whether a `url` contains `http`.
  If it does, it adds `rel="external noopener"` automatically — you don't
  set `rel` yourself. (There's no `target="_blank"`; external links open in
  the same tab.) The `Member Portal` link under Membership
  (`https://mp.gg/0-1eb`) is an example already in the file.

Keep the file's 2-space indentation and don't leave a trailing comma on the
last item — it's plain JSON, not JS.

## Current-page highlighting

`header.liquid` adds `aria-current="page"` when `page.url` matches an
item's `url` **exactly**, as a string:

```liquid
{% if page.url == item.url %} aria-current="page"{% endif %}
```

`assets/css/site.css` then styles it: `.nav-list a[aria-current="page"] {
color: var(--color-accent); }`.

Two gotchas:

- **Trailing slash matters.** `page.url` is generated by Eleventy with a
  trailing slash (e.g. `/dissertation/`). If a `url` in `navigation.json`
  is missing the trailing slash, it will never match and the item will
  never highlight — even though the link itself still works fine.
- **Dropdown parents highlight through a hidden duplicate link, not the
  visible summary.** The visible label for a dropdown item is a
  `<summary>` element, which the CSS selector above does not target. The
  actual `aria-current` check runs on the *first link inside the dropdown
  list* (the repeated copy of the parent's own `url`), which is only
  visible once the dropdown is open. In practice this means: visiting
  `/meetings/` will **not** visibly highlight the "Meetings" label in the
  collapsed row, even though the underlying markup is technically correct.

## Why "Home" doesn't appear

`header.liquid` explicitly skips it:

```liquid
{% if item.url == "/" %}{% continue %}{% endif %}
```

The `Home` entry stays in `navigation.json` (first item, `"url": "/"`) but
is never rendered — this is intentional, since the masthead title/logo
already links to `/`. To bring "Home" back into the nav row, delete that
`{% if %}...{% continue %}{% endif %}` line in `_includes/header.liquid`
(a template change, not a data change).

The membership portal is not in the nav either. The masthead's top-left
"Become a Member" link (hardcoded in `header.liquid`, pointing at
`https://mp.gg/0-1eb`) carries that job, and `/membership/` sits under
About. An earlier "Join" item at the end of the nav row was a third copy of
the same destination, so it is gone.

## How many items fit

Above `60rem` the nav switches to `.nav-list { display: flex; flex-wrap:
wrap; justify-content: center; column-gap: var(--space-sm); }` — a single
centred rule row inside the site's `74rem` shell. Labels are uppercase and
bold with `letter-spacing`, which makes each one noticeably wider than its
plain character count; between `60rem` and `76rem` a second media query
drops them to `--text-xs` with a tighter gap so the row survives narrow
desktops. Items with a `dropdown` also carry a caret icon, which costs
roughly another 16px each.

As a rule of thumb: the current file renders 7 top-level items (two of them
with dropdowns) and holds one row all the way down to 960px. Around ten
top-level items it starts wrapping to a second line at narrow desktop
widths, which breaks the "single rule row" look — it's a flex wrap, not a
designed second-row layout. If you add or rename items, check the header at
a **narrow desktop width** (just above `60rem` / 960px, not a wide monitor);
that's where wrapping shows up first. Prefer putting new links inside an
existing `dropdown` rather than adding another top-level item.

Below `60rem`, the whole nav collapses into the native `<details>`/`<summary>`
"Menu" disclosure (`.site-nav`) and items stack vertically as a single
column — the item-count limit above doesn't apply there.

## What NOT to touch for nav changes

- **Footer links are separate files**, not part of the nav: the "Society"
  column comes from `_data/services.json` and the "PRSt" column comes from
  `_data/network.json`, both rendered by `_includes/footer.liquid`. Editing
  `navigation.json` has no effect on the footer, and vice versa.
- **Blog category chips** (Announcements, Calls for papers, Positions,
  Books, Meetings, Scholarships) are not nav items at all — they come from
  the `BUCKET_PAGES` array in `eleventy.config.js`.

## Checking your change

```sh
npm run build && npm run check
```

`scripts/check-build.mjs` walks every built HTML file and verifies every
internal `href`/`src` resolves to a real file in `_site/`. A typo'd `url`
in `navigation.json` (missing slash, wrong path, etc.) will fail the build
here with a `missing internal target ...` error — this is the main way a
bad nav link gets caught before it ships. External (`http...`) links are
not checked this way; verify those by hand.
